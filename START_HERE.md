## 🚀 Résumé des étapes

### 1️⃣ Supabase (5 min)
- Créer compte supabase.com
- Copier URL + Clé
- Exécuter `supabase_migration.sql`

### 2️⃣ Configuration locale (3 min)
- Remplir `.env.local` avec clés Supabase
- `npm install`

### 3️⃣ Tester en local (3 min)
- `npm run dev`
- Accès à http://localhost:3000/public/index.html

- `git init` + `git add` + `git commit`
- Créer repo GitHub
- `git push`

### 5️⃣ Vercel (7 min)
- Importer projet depuis GitHub
- Ajouter variables d'environnement
- Deploy!

## ⚠️ Points importants à retenir

### 🔐 Sécurité
- **`.env.local` ne doit JAMAIS être commité** (c'est dans `.gitignore` ✅)
- Vérifiez que `.env.local` n'est PAS dans Git

### 🔑 Clés Supabase
- Utilisez la clé `anon` (pas `service_role`)
- Gardez les clés secrètes

### 🌐 Supabase vs Vercel
- **Supabase** = Base de données + API (vos données)
- **Vercel** = Hébergement statique (votre site)
- Les deux gratuits au départ!

## 💡 Questions fréquentes

**Q: Je dois modifier quelque chose après le déploiement?**
A: Non, c'est tout prêt. Modifiez juste votre code local et push sur GitHub, Vercel redéploie auto.

**Q: Les images s'affichent?**
A: Oui, elles sont dans `public/images/`. Les chemins sont conservés.

**Q: Mes anciennes données?**
A: À migrer de MySQL vers Supabase. Voir `DEPLOY_GUIDE.md` section "Migration des Données".

**Q: C'est vraiment gratuit?**
A: Oui! Vercel free + Supabase free tier. Zéro coût initialement.

**Q: Et si je veux ajouter une authentification?**
A: Supabase Auth est intégré. Ajoutez-la plus tard, ce n'est pas compliqué.
